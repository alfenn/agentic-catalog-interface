# Midway report review

## Assessment

The existing deliverable is a report source and generated PDF, reproducible local dbt/DuckDB experiments, saved pilot results and audit, and a scripted demo. The staff clarification in [Ed threads](../../writeups/midway_report/requirements/ed_threads.md) explicitly accepts a research-pipeline demo and one collected result, with a README explaining reproduction. The present scope is appropriate; a hosted UI is not needed to satisfy that clarification. The report explains the problem, constructed data, methods, metrics, obstacles, results, assets, risks and milestones. Its strongest feature is its unusually candid treatment of pilot limitations.

## Priority findings and changes

1. **Submission is incomplete.** [Report source](../../writeups/midway_report/report.md) still has placeholders for the video URL and the author's actual human verification. Record a video of at most three minutes, upload it, check playback and course-staff access, submit the URL as directed, and replace the placeholders with the true URL and specific verification actually performed. The [video requirements](../../writeups/midway_report/requirements/video.md) govern submission; the script's target duration is not evidence of a finished recording. Confirm repository accessibility and final PDF page-count convention against the [report requirements](../../writeups/midway_report/requirements/midway_report.md).
2. **The previous demo's no-cost guarantee was unsound.** The budget guard checked accumulated spend before a call, so an empty cache and ledger could permit the first paid call. [Demo commands](../../writeups/midway_report/demo/demo_commands.sh) now display saved pilot artifacts for model results without calling a model; the [run sheet](../../writeups/midway_report/demo/demo_script.md) reflects this. Prep still builds local fixtures and figures. This directly demonstrates the collected result, and does not depend on an ignored response cache.
3. **Verification and the apparent longitudinal demonstration needed qualification.** The demo now says its two fixtures reset independently, despite matching description text, and that field equality plus dbt parsing does not establish semantic correctness. The report now distinguishes the three patch values judged correct from the wrong-grain action outside the episode's acceptable set. The [audit](../../experiments/results/midpoint_v1_2_pilot/analysis.md) shows that neither agent supplied uniqueness evidence for that case. No safety or remediation-effectiveness advantage is established.
4. **Grounding and sensitivity needed precision.** A resolving evidence ID is not proof of support. The report and audit introduction now acknowledge the partially unsupported steward conclusion recorded in the audit's detailed grounding totals. The report identifies its three sensitivity numbers as separate illustrative rule changes, not a shared interval or rescoring. The pilot records and labels remain unchanged.
5. **The comparison is bundled and small.** Evidence bundle, action rules, validation, and tools differ together; generic patches are plan-only and protocol rejections differ. Ten author-built episodes, one sample each, contaminated clean controls and four reused preliminary records limit inference. The report now explicitly says it does not isolate an interface effect. Future work should prioritize independently reviewed labels and clean controls, episode-specific postconditions and unsafe-action checks, a fairer generic baseline, and ablations before claiming a mechanism or general safety benefit.
6. **Reproduction is distinct from a new model run.** [README](../../README.md) now distinguishes regenerating the report from checked-in results from a paid, variable new sample. The response cache is not a portable checkout dependency. The example now writes a new run to a separate directory: the evaluator overwrites JSON and merges artifact directories, so reusing the cited pilot folder risks corrupting its provenance. A fresh environment still needs an end-to-end setup and build check; no fresh paid run is necessary to inspect the saved result.
