# Midpoint recorded-demo runbook

Run from the repository root after `make setup`. This is a local fixture demonstration. The two episodes are connected conceptually; each resets independently from its own fixture, so the second does not carry forward a patch from the first.

1. **Frame the contract.** Show `make contract` and explain that the steward gathers evidence and produces reviewable patches, proposals or reports. It does not mutate a live catalog or decide business semantics on its own.
2. **Remediate existing drift.** Run `make fixture EPISODE=rem_daily_revenue_filter_drift` and `make evidence EPISODE=rem_daily_revenue_filter_drift ASSET=daily_revenue`. The evidence command resets the workspace again without building it. Compare `.runs/rem_daily_revenue_filter_drift/project/catalog/overrides.json` with the model SQL and parsed facts: catalog prose says all orders, while SQL filters to completed orders. The expected outcome is a reviewable description correction or proposal, with SQL unchanged. If a live credential is available, run `make steward EPISODE=rem_daily_revenue_filter_drift` and inspect its JSON result and the `artifacts/` folder of the workspace it prints (under `.runs/steward/`); show what actually happened, including any failure or unresolved issue.
3. **Review a new change.** Run `make fixture EPISODE=change_daily_revenue_filter` and `make evidence EPISODE=change_daily_revenue_filter ASSET=daily_revenue`. Show `.runs/change_daily_revenue_filter/input.diff` and compare the changed filter with the completed-only metadata. The contribution includes refunded orders; whether they belong in revenue requires a semantic decision. If live access is available, run `make steward EPISODE=change_daily_revenue_filter` and inspect the actual findings and verification.
4. **Compare the baseline.** Inspect the checked-in `experiments/results/midpoint_v1_static/rem_daily_revenue_filter_drift/static.json` and `experiments/results/midpoint_v1_static/change_daily_revenue_filter/static.json`, alongside `experiments/results/midpoint_v1_static/summary.json`. Static required-field and dbt-test checks recorded no finding for the remediation drift; inspect the change result rather than assuming its outcome. The checked-in summary reports 4 of 10 fixture-level episode successes, not remediation successes. Use the [static results audit](../experiments/results/midpoint_v1_static/analysis.md) as the interpretation guide. The summary does not contain a completed generic or steward pilot.
5. **Close honestly.** Without a valid live credential and completed live pilot, show the fixture, evidence, expectations and static records, and do not claim the steward succeeded or outperformed a baseline. For a paid run, check `make doctor-live`, budget and `make costs` first. See the [README](../README.md) for output locations and reproducibility details.
